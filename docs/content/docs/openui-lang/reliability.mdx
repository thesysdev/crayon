---
title: Reliability
description: Reduce, detect, and correct errors in model-generated OpenUI interfaces.
---

Generative UI puts model output directly into an interface. Models can invent components, use unsupported values, leave references unresolved, or stop before the program is complete. A reliable application needs defenses before, during, and after generation.

In our [Reliability benchmark](/blog/generative-ui-benchmark), every tested format produced incomplete generations. OpenUI completed 92.9% of the evaluated tasks and produced only two blank screens across 1,104 runs, but even its strongest model pairing did not reach 100%.

## Four reliability layers

1. **Component design:** Use distinct names, focused schemas, unambiguous enum values, and clear descriptions. Remove overlapping components and group related components together. See [Defining Components](/docs/openui-lang/defining-components).
2. **System prompts:** Add focused rules for recurring failures and valid examples for compositions the model finds difficult. See [System Prompts](/docs/openui-lang/system-prompts).
3. **Model evaluation:** Test representative prompts repeatedly and compare completion rate, latency, and cost across models.
4. **Runtime correction:** Validate generated OpenUI Lang during the stream and correct errors before they reach users. The [Gateway](/docs/gateway/reliability/error-correction) provides this production layer.

Measure before and after changing one of these layers so you can tell whether the intervention fixed the original failure or merely moved it.

## During development

OpenUI DevTools captures parser and renderer errors while an interface streams. Inspect the response text, validation details, parsed tree, and streaming timeline in the application where the failure occurred.

When using `@openuidev/react-lang`, DevTools is automatically available in browser development builds. See [Developer Tools](/docs/openui-lang/developer-tools) for the local debugging workflow.

## In production

Development prompts cannot represent every request users will send. [OpenUI Observability](/docs/observability) captures runtime errors across production traffic so you can group recurring failures, inspect affected generations, and verify improvements.

Observability works whether requests use the Gateway or call a model provider directly. It is a separate product from the local `@openuidev/observability` event bus and from OpenUI Lang's limited project telemetry.

## Correct errors in the stream

The Gateway is the recommended production generation path. For OpenUI requests, it continuously validates the language and repairs correctable syntax, reference, component, and schema errors before forwarding the stream to the application. It can also recover from model or provider availability failures through fallbacks.

In production benchmark data, the Gateway fixed **96% of generations** that initially failed validation.

Continue with [Gateway Reliability](/docs/gateway/reliability) for correction and fallback behavior, or [Optimizing with Observability](/docs/observability/optimizing) for the production feedback loop.
