Blocks are the core building units of OpenUI. Think of them as small, self-contained UI primitives that can be combined to create rich, structured generative interfaces.

Each block represents a specific pattern of structured data, such as navigation, cards, callouts, tables, charts, and forms. Because blocks are designed for generative UI, they provide a flexible and composable foundation while keeping generated interfaces consistent, predictable, and easy to evolve.

## How blocks compose

Composition is how individual blocks come together to form complete interfaces.

The model assembles blocks based on its understanding of the content and context. Given information and intent, it selects the blocks that best fit the information hierarchy and user experience. This allows interfaces to be generated dynamically while maintaining visual and structural consistency.

You remain in control of this behavior. Use [system prompts](/docs/openui-lang/system-prompts) and usage rules to guide composition by:

- defining when a particular block should be preferred
- specifying which block to use for a particular context
- discouraging blocks in contexts where they are not appropriate

## Understanding configurations

Many blocks expose prompt-level configurations that control their content and presentation. These configurations allow one block to support several useful variations without requiring a separate component for each variation.

When a configuration is not specified, the model selects the variation that best fits the generated context. There is no fixed documentation default implied by the configuration tables.

When you need more control or consistency, explicitly steer configuration selection through your system prompt. The pages in this section document only generation choices that can be requested through prompting—not implementation props or Storybook controls.
