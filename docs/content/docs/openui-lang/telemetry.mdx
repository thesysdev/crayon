---
title: Telemetry
description: What OpenUI Lang collects, why it is collected, and how to control installation and runtime telemetry.
---

OpenUI Lang Core has two types of telemetry:

- **Installation telemetry** is on by default. You can turn it off.
- **Runtime telemetry** is off by default. You can choose to turn it on.

## Why we collect it

Telemetry helps us understand how OpenUI Lang is used, which environments we should support, and where to focus reliability and performance work.

Telemetry is optional and never blocks installation or prompt generation if it fails.

## Installation telemetry

Installation telemetry runs when `@openuidev/lang-core` is installed. It does not run during your application build unless that build also installs dependencies.

### What we collect

- A random ID for the installation
- A project identifier created locally so the original repository URL or path is not sent
- OpenUI Lang Core, Node.js, operating system, and package manager versions
- Whether the installation is running in CI or Docker

### Opt out

Set either variable when installing dependencies:

```bash
OPENUI_TELEMETRY_DISABLED=1 pnpm install
```

or:

```bash
DO_NOT_TRACK=1 pnpm install
```

These variables also work with npm, Yarn, and Bun. In CI, set one before the dependency-install step.

## Runtime telemetry

Runtime telemetry is off by default. When enabled, OpenUI Lang samples successful prompt generations on your server and sends telemetry for about 1 in 10 of them. Browser calls never send runtime telemetry.

### What we collect

- OpenUI Lang Core and server runtime versions
- Environment and CI information
- The number of components and tools in the prompt setup
- Project and prompt-setup identifiers created locally; the original values are not sent

### Opt in

Set the opt-in variable in the server environment where `generateSystemPrompt()` runs:

```bash
OPENUI_RUNTIME_TELEMETRY_ENABLED=1 pnpm dev
```

For a deployed application, set this variable in the server environment where `generateSystemPrompt()` runs.

To turn runtime telemetry off again, remove `OPENUI_RUNTIME_TELEMETRY_ENABLED` or set a global disable flag:

```bash
OPENUI_TELEMETRY_DISABLED=1
```

The disable flags always win. Runtime telemetry stays off if `OPENUI_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1` is set, even when the runtime opt-in is also set.

## What we never collect

Neither telemetry flow sends:

- Prompts, messages, preambles, examples, additional rules, or generated output
- Source code or full component, tool, or schema definitions
- Repository URLs, project names, file paths, branches, or commits
- Names, email addresses, usernames, user IDs, or chat data
- Credentials, API keys, environment values, errors, logs, or stack traces
- Routes, DOM data, or UI interactions

Telemetry is sent through an OpenUI endpoint to PostHog. Like any web request, the endpoint and PostHog can see the source IP, but OpenUI Lang does not add it to the telemetry data.

<Callout type="info">
  This page covers telemetry in `@openuidev/lang-core`. The OpenUI CLI has separate command
  telemetry. See the [CLI telemetry documentation](/docs/api-reference/cli#telemetry) for its data
  boundaries and `--no-telemetry` control.
</Callout>
