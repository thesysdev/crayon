---
title: Reliability
description: Keep OpenUI generation usable when models return invalid language or providers become unavailable.
---

Model output and provider availability are both nondeterministic. The Gateway handles these as two different failure classes so applications do not need to build the same recovery infrastructure around every model call.

## Two reliability layers

<Cards>
  <Card title="Error Correction" href="/docs/gateway/reliability/error-correction">
    Validate OpenUI Lang during generation and repair correctable syntax, reference, component, and
    schema errors before they reach the renderer.
  </Card>
  <Card title="Provider Fallbacks" href="/docs/gateway/reliability/provider-fallbacks">
    Recover from model or provider availability failures through a compatible fallback route.
  </Card>
</Cards>

These layers complement the reliability techniques in the open-source stack. Clear component definitions, focused system prompts, representative evaluations, and renderer error boundaries are still important. See [OpenUI Lang Reliability](/docs/openui-lang/reliability) for the complete application-level approach.

## Close the loop with Observability

Gateway correction reduces failures before a response reaches the application. [Observability](/docs/observability) captures errors from the OpenUI runtime so you can see which prompts, components, and model choices still need attention in production.
