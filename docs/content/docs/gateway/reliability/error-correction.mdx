---
title: Error Correction
description: Learn how the Gateway validates and corrects OpenUI Lang while a response streams.
---

The Gateway continuously validates OpenUI Lang as the model produces it. Correction happens in the streaming path, without waiting for the complete interface or asking the application to retry the generation.

## What is checked

The validation pipeline can identify problems such as:

- Malformed OpenUI Lang statements
- References that cannot resolve
- Components that are not present in the supplied library
- Property values that violate a component schema
- Structures the renderer cannot safely construct

When an error is correctable, the Gateway fixes the affected output and continues the stream. Valid parts of the interface can keep rendering progressively.

## Scope

Error correction applies to OpenUI Lang generation. Plain text, arbitrary JSON, application tool results, and user-written component code are outside this correction boundary.

Your application should still use renderer error boundaries and [Observability](/docs/observability) because not every runtime or application error originates in generated language.

## Improving results

Correction is a production safety layer, not a substitute for a clear component contract. You will get better latency and more consistent interfaces when component schemas are distinct, system prompts contain valid examples, and models are evaluated against representative requests. See [OpenUI Lang Reliability](/docs/openui-lang/reliability).
