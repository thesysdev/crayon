---
title: Provider Fallbacks
description: Recover Gateway requests when a selected model or provider is unavailable.
---

Provider fallbacks protect an application from availability failures outside its control. When the selected route cannot serve a request, the Gateway can retry through a compatible fallback without requiring a separate provider integration in the application.

## When fallback applies

Fallbacks are intended for provider and model availability failures such as outages, temporary capacity limits, and unavailable routes. They are separate from [OpenUI Lang error correction](/docs/gateway/reliability/error-correction), which operates on output a model has already generated.

## What remains stable

The application continues to use the same Gateway API and `{provider}/{model}` naming convention. The Gateway normalizes provider differences so the response remains compatible with the selected Responses or Chat Completions surface.

<Callout type="info">
  The exact fallback route depends on model compatibility and account configuration. Confirm the
  active behavior for your project in the Thesys Console before relying on it for a strict model or
  data-residency requirement.
</Callout>

Use [Observability](/docs/observability) to understand the runtime errors seen by the application after routing and correction have completed.
