The OpenUI Gateway is the recommended way to generate OpenUI Lang in production. It sits between your application and model providers, keeps the API surface consistent across models, and handles failures that would otherwise reach the interface.

Your components and renderer remain in your application. The Gateway is responsible for the generation path.

## What the Gateway does

- **Routes model requests:** Use one API across supported models and providers.
- **Corrects OpenUI Lang:** The Gateway validates generated UI during the stream and fixes malformed syntax, invalid component usage, and schema violations before forwarding the response.
- **Handles provider failures:** When the selected model or provider is unavailable, the Gateway can move the request to a compatible fallback.
- **Supports persistent conversations:** Responses can reference stored conversation state instead of resending the full history on every turn.
- **Runs hosted tools:** Responses applications can enable supported tools without operating the tool runtime themselves.

The Gateway and Observability are separate products. You can use the Gateway without Observability, or send telemetry from an application that calls a model provider directly. Together they form a feedback loop: the Gateway prevents known generation failures from reaching users, while [Observability](/docs/observability) reveals the errors that still occur at runtime.
