OpenUI Cloud is the managed layer that runs OpenUI applications in production. Open-source OpenUI and Cloud share the same foundation — OpenUI Lang and the rendering model are identical in both — and Cloud adds the layers around it: model access with automatic fallbacks, output validation, artifact generation, and conversation persistence. Teams ship the product rather than operating the infrastructure.

## Generative UI for agents

The agent composes the interface for each response — a form when it needs input, the right chart for the data, tabs and cards for long answers — validated, streamed, and rendered live in the application.

### Built-in component library

[Production-grade components](/docs/openui-cloud/build/chat) for the interfaces agents build: forms and inputs, interactive charts, layout components for organizing content, and actions that feed back into the conversation.

### Bring your own component library

Applications can bring their own component library — their design system and custom components — and Cloud's production features apply to it: output validation, model reliability, and consistent behavior across models and providers.

## Slides

Complete presentations generated from a conversation. Every slide renders from a professionally designed [slide template](/docs/openui-cloud/build/slides), decks stay editable through conversation, and each exports through a print-ready layout.

## Production ready

- **[Model access & fallbacks](/docs/openui-cloud/production-readiness#reliable-model-access)** — models from supported providers through Cloud's APIs, billed at cost; requests reroute automatically when a model or provider is unavailable.
- **[Output validation & correction](/docs/openui-cloud/production-readiness#output-validation--correction)** — every response validated against its component library and corrected in the stream; broken model output does not reach the interface.
- **[Conversation persistence](/docs/openui-cloud/production-readiness#conversation-persistence)** — threads and artifacts stored and versioned automatically; no database on the application side.
- **Observability** — visibility into render success, latency, and cost across a deployment. *Coming soon.*

To scaffold a working application, see [Get Started](/docs/openui-cloud/get-started). For the architecture, see [How it works](/docs/openui-cloud/how-it-works).
