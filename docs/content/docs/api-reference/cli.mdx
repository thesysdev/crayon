A command-line tool for scaffolding OpenUI apps, minting OpenUI Gateway API keys, generating system prompts and library specs from a component library, and deploying apps.

## Installation

Run without installing:

```bash tab="pnpm" tab-group="pkg"
pnpx @openuidev/cli@latest <command>
```

```bash tab="bun" tab-group="pkg"
bunx @openuidev/cli@latest <command>
```

```bash tab="yarn" tab-group="pkg"
yarn dlx @openuidev/cli@latest <command>
```

```bash tab="npm" tab-group="pkg"
npx @openuidev/cli@latest <command>
```

Or install globally:

```bash tab="pnpm" tab-group="pkg"
pnpm add -g @openuidev/cli
```

```bash tab="bun" tab-group="pkg"
bun add -g @openuidev/cli
```

```bash tab="yarn" tab-group="pkg"
yarn global add @openuidev/cli
```

```bash tab="npm" tab-group="pkg"
npm install -g @openuidev/cli
```

## Global options

Available on every command.

| Flag                  | Description                                                                                                   |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| `--agent-name <name>` | Coding agents: declare your product slug, e.g. `codex` or `claude-code` (see [Coding agents](#coding-agents)) |
| `--verbose`           | Stream full command logs                                                                                      |
| `--no-telemetry`      | Disable anonymous usage analytics (`DO_NOT_TRACK=1` also works)                                               |
| `-V, --version`       | Print the CLI version                                                                                         |
| `-h, --help`          | Show help for a command                                                                                       |

## `create`

Scaffolds a generative UI agent with Next.js and your choice of agent framework. No account or API key is needed to scaffold; add the key afterwards with [`generate-api-key`](#generate-api-key).

```
openui create [directory] [options]
```

**Options**

| Flag                              | Description                                                                                              |
| --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `-n, --name <string>`             | Project name (default: `openui-agent`)                                                                   |
| `--backend-framework <framework>` | Backend framework: `langgraph` (default), `vercel-ai-sdk`, or `vercel-eve`                               |
| `-e, --example <example>`         | Scaffold an [OpenUI example](https://github.com/thesysdev/openui/blob/main/examples) instead             |
| `--no-skill`                      | Skip the [OpenUI agent skill](/docs/mcp#install-via-the-skills-cli-recommended) for AI coding assistants |
| `--no-install`                    | Scaffold without installing dependencies                                                                 |
| `-i, --immediate`                 | Start the development server after installing                                                            |
| `--no-immediate`                  | Install dependencies without starting the development server                                             |
| `--no-interactive`                | Never prompt; use defaults for anything not passed                                                       |

`--example` cannot be combined with `--backend-framework`. `--immediate` and `--no-immediate` cannot be used together.

**Interactive and non-interactive runs**

In a terminal, `create` prompts for anything you didn't pass: the project name, a backend framework or example, and Gateway sign-in. It then installs dependencies and starts the development server.

When nobody can answer prompts, `create` takes the defaults instead: `langgraph` and the name `openui-agent` (or `openui-agent-2`, `-3`, … if that directory exists). This happens when you pass `--no-interactive`, when there's no terminal attached (CI, scripts), or when a coding agent runs the CLI. In that mode it:

- installs dependencies but doesn't start the development server (pass `--immediate` to start it)
- skips Gateway sign-in and ends with the `generate-api-key` command to run next

An explicit `--name` that already exists is an error in non-interactive runs.

Pass `.` as the directory (`openui create .`) to scaffold into the current folder instead; it must be empty apart from editor or agent folders such as `.git`, `.vscode` or `.claude`, and the project is named after the folder.

**Backend frameworks**

| Value           | Description                                |
| --------------- | ------------------------------------------ |
| `langgraph`     | LangGraph agent                            |
| `vercel-ai-sdk` | Vercel AI SDK agent                        |
| `vercel-eve`    | Eve agent rendered through Agent Interface |

**OpenUI examples**

Loaded from [OpenUI examples](https://github.com/thesysdev/openui/blob/main/examples). Pass `--example <name>` with any catalog folder name; it can't be combined with `--backend-framework`.

**Examples**

```bash tab="pnpm" tab-group="pkg"
# Prompt for anything not passed
pnpx @openuidev/cli@latest create

# Pick a backend framework, or start from an example
pnpx @openuidev/cli@latest create --name my-app --backend-framework vercel-ai-sdk
pnpx @openuidev/cli@latest create --name my-app --example shadcn

# Never prompt, then add the key
pnpx @openuidev/cli@latest create --no-interactive --name my-app
cd my-app && pnpx @openuidev/cli@latest generate-api-key
```


## `deploy`

Deploys an OpenUI project to Vercel.

```
openui deploy [dir] [options]
```

**Arguments**

| Argument | Description                                    |
| -------- | ---------------------------------------------- |
| `[dir]`  | Project directory (default: current directory) |

**Options**

| Flag               | Description                                                               |
| ------------------ | ------------------------------------------------------------------------- |
| `-y, --yes`        | Skip confirmation prompts and save missing env keys to the Vercel project |
| `--skip-env`       | Don't pass or save local `.env` / `.env.local` values                     |
| `--no-interactive` | Skip prompts (implies `--yes`)                                            |

Any other flags, such as `--prod`, are passed through to Vercel. Unlinked projects are linked first. Build logs are hidden unless you pass `--verbose`; failures always print the end of the log.

```bash tab="pnpm" tab-group="pkg"
# Preview deploy from the project directory
pnpx @openuidev/cli@latest deploy

# Production deploy
pnpx @openuidev/cli@latest deploy --prod --yes

# Deploy a specific directory without local env
pnpx @openuidev/cli@latest deploy ./my-app --skip-env
```

```bash tab="bun" tab-group="pkg"
# Preview deploy from the project directory
bunx @openuidev/cli@latest deploy

# Production deploy
bunx @openuidev/cli@latest deploy --prod --yes

# Deploy a specific directory without local env
bunx @openuidev/cli@latest deploy ./my-app --skip-env
```

```bash tab="yarn" tab-group="pkg"
# Preview deploy from the project directory
yarn dlx @openuidev/cli@latest deploy

# Production deploy
yarn dlx @openuidev/cli@latest deploy --prod --yes

# Deploy a specific directory without local env

```

```bash tab="npm" tab-group="pkg"
# Preview deploy from the project directory
npx @openuidev/cli@latest deploy

# Production deploy
npx @openuidev/cli@latest deploy --prod --yes

# Deploy a specific directory without local env
npx @openuidev/cli@latest deploy ./my-app --skip-env
```

## `generate-api-key`

Signs in with Thesys in the browser, mints an OpenUI Gateway API key, and writes it to an env file in the current project. It needs an interactive terminal; without one it exits with the command to run yourself.

```
openui generate-api-key [options]
```

**Options**

| Flag                  | Description                                                                                     |
| --------------------- | ----------------------------------------------------------------------------------------------- |
| `-f, --file <path>`   | Env file to write (default: `.env`)                                                             |
| `-k, --key <name>`    | Environment variable name (default: `THESYS_API_KEY`)                                           |
| `-n, --name <string>` | Name of the key in the Thesys console (default: the `package.json` name, or the directory name) |

**Examples**

```bash tab="pnpm" tab-group="pkg"
pnpx @openuidev/cli@latest generate-api-key
pnpx @openuidev/cli@latest generate-api-key --file .env.local
```

```bash tab="bun" tab-group="pkg"
bunx @openuidev/cli@latest generate-api-key
bunx @openuidev/cli@latest generate-api-key --file .env.local
```

```bash tab="yarn" tab-group="pkg"
yarn dlx @openuidev/cli@latest generate-api-key
yarn dlx @openuidev/cli@latest generate-api-key --file .env.local
```

```bash tab="npm" tab-group="pkg"
npx @openuidev/cli@latest generate-api-key
npx @openuidev/cli@latest generate-api-key --file .env.local
```

## `generate`

Generates the system prompt **and** the serialized library spec from a file that exports a `createLibrary()` result. Use the spec with `generateSystemPrompt` in backend routes; the prompt file supports static or legacy integrations.

```
openui generate [entry] [options]
```

**Arguments**

| Argument  | Description                                                             |
| --------- | ----------------------------------------------------------------------- |
| `[entry]` | Path to a `.ts`, `.tsx`, `.js`, or `.jsx` file that exports a `Library` |

**Options**

| Flag                      | Description                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------- |
| `-o, --out <file>`        | Write the prompt to `<file>`; the spec uses the same basename with a `.spec.json` extension |
| `--json-schema`           | Output only the JSON schema; it is not the input to `generateSystemPrompt`                  |
| `--spec`                  | Output only the serialized library spec                                                     |
| `--export <name>`         | Name of the library export to use                                                           |
| `--prompt-options <name>` | Name of the `PromptOptions` export to use                                                   |
| `--no-interactive`        | Fail instead of prompting for a missing `entry`                                             |

Without `--export`, the CLI uses an export named `library`, then the `default` export, then any export that is a library. Without `--prompt-options`, it uses an export named `promptOptions`, then `options`, then any export whose name ends with `PromptOptions`.

**Examples**

```bash tab="pnpm" tab-group="pkg"
# Print the system prompt to stdout
pnpx @openuidev/cli@latest generate ./src/library.ts

# Write the prompt and its .spec.json alongside it
pnpx @openuidev/cli@latest generate ./src/library.ts --out ./src/generated/system-prompt.txt

# Output only the spec or the JSON schema
pnpx @openuidev/cli@latest generate ./src/library.ts --spec
pnpx @openuidev/cli@latest generate ./src/library.ts --json-schema

# Explicit export names
pnpx @openuidev/cli@latest generate ./src/library.ts --export myLibrary --prompt-options myOptions
```

```bash tab="bun" tab-group="pkg"
# Print the system prompt to stdout
bunx @openuidev/cli@latest generate ./src/library.ts

# Write the prompt and its .spec.json alongside it
bunx @openuidev/cli@latest generate ./src/library.ts --out ./src/generated/system-prompt.txt

# Output only the spec or the JSON schema
bunx @openuidev/cli@latest generate ./src/library.ts --spec
bunx @openuidev/cli@latest generate ./src/library.ts --json-schema

# Explicit export names
```

### `PromptOptions`

Export a `PromptOptions` object next to your library to customize the generated system prompt.

```ts
interface PromptOptions {
  preamble?: string;
  additionalRules?: string[];
  examples?: string[];
  toolExamples?: string[];
  editMode?: boolean;
  inlineMode?: boolean;
  /** Enable Query(), Mutation(), @Run, built-in functions. Default: true if tools provided. */
  toolCalls?: boolean;
  /** Enable $variables, @Set, @Reset, built-in functions. Default: true if toolCalls. */
  bindings?: boolean;
}
```

Built-in functions (`@Count`, `@Filter`, `@Sort`, `@Each`, etc.) are included in the prompt only when `toolCalls` or `bindings` is enabled.

```ts
// src/library.ts
import { createLibrary } from "@openuidev/react-lang";
import type { PromptOptions } from "@openuidev/react-lang";

export const library = createLibrary({ components: [...] });

export const promptOptions: PromptOptions = {
  preamble: "You are a dashboard builder...",
  additionalRules: ["Always use compact variants for table cells."],
};
```

## `setup-agent`

Adds OpenUI instructions for coding agents to an existing project. It appends the [OpenUI skill](https://github.com/thesysdev/skills) to `AGENTS.md`, or creates the file. Running it again refreshes the OpenUI instructions and leaves the rest of the file alone. Projects made with `create` already have it.

```
openui setup-agent [directory]
```

`directory` defaults to the current folder.

```bash tab="pnpm" tab-group="pkg"
pnpx @openuidev/cli@latest setup-agent
```

```bash tab="bun" tab-group="pkg"
bunx @openuidev/cli@latest setup-agent
```

```bash tab="yarn" tab-group="pkg"
yarn dlx @openuidev/cli@latest setup-agent
```

```bash tab="npm" tab-group="pkg"
npx @openuidev/cli@latest setup-agent
```

## `feedback`

Sends anonymous feedback to the OpenUI team. It isn't linked to your account, device, or IP address, and it's sent even when telemetry is disabled. Don't include personal data, secrets, or code.

```
openui feedback [options] <message...>
```

**Options**

| Flag                        | Description                          |
| --------------------------- | ------------------------------------ |
| `-c, --category <category>` | `bug`, `feature`, `docs`, or `other` |

```bash tab="pnpm" tab-group="pkg"
pnpx @openuidev/cli@latest feedback --category docs "The streaming guide doesn't cover partial components"
```

```bash tab="bun" tab-group="pkg"
bunx @openuidev/cli@latest feedback --category docs "The streaming guide doesn't cover partial components"
```

```bash tab="yarn" tab-group="pkg"
yarn dlx @openuidev/cli@latest feedback --category docs "The streaming guide doesn't cover partial components"
```

```bash tab="npm" tab-group="pkg"
npx @openuidev/cli@latest feedback --category docs "The streaming guide doesn't cover partial components"
```

## Coding agents

Coding agents should pass `--agent-name` with their stable, lowercase kebab-case product slug, such as `codex`, `claude-code`, `cline`, `factory-droid`, or `pi`. Don't pass a model version, user name, or session ID. Humans can omit it.

`create` never waits on a prompt when an agent runs it, whether or not `--agent-name` is passed: it takes its [non-interactive defaults](#create) and prints any follow-up commands, such as `generate-api-key`, at the end. Its last line points the agent at the new project's README to get started.

## Telemetry

The CLI sends usage analytics: which commands and flags are used, and bounded failure codes. Browser sign-in may link usage to your Thesys account ID. It never sends code, prompts, API keys, env values, project paths, or command output. Disable it with `--no-telemetry` or `DO_NOT_TRACK=1`.
