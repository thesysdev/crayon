Framework-agnostic event bus for observing what happens inside an OpenUI app — fetch calls, LLM calls, renderer outcomes, whatever your app cares about — through one fixed, generic interface modeled on a toast library's contract. Zero dependencies, safe on server and browser. A single shared instance per app; third-party sinks (Sentry, Datadog, custom loggers) attach with one `listenAll` call.

## `observability`

The shared bus. It is **itself callable** — `observability(level, detail)` — with level shortcuts and listen methods hanging off it. There is one shared instance — import it anywhere; emitters and listeners meet on it.

```ts
import { observability, toErrorInfo } from "@openuidev/observability";

// Call the bus with an explicit level and a payload.
observability("error", { kind: "renderer:error", component: "Chart", error: toErrorInfo(err) });

// Level shortcuts:
observability.error({ kind: "llm:timeout", requestId, message: "timed out" });
observability.warn({ kind: "chart:overflow", component: "Chart", points: 1200 });
observability.info({ kind: "route:change", to: "/settings" });

// Listen by level (one or several), or to everything (the sink attachment point).
const remove = observability.listen("error", (event) => console.error(event.detail));
const some = observability.listen(["warning", "error"], (event) => report(event));
const detach = observability.listenAll((event) => {
  if (event.level === "error") {
    // forward event.detail to your service
  }
});
```

Every method returning a listener gives back an `Unsubscribe` remover, and a listener that throws never breaks the emitter or other listeners.

## The event envelope

Every listener receives the same fixed envelope:

```ts
interface ObservabilityEvent {
  level: "info" | "warning" | "error";
  timestamp: number; // ms since epoch
  detail: ObservabilityDetail;
}
```

## The detail

`detail` is a typed shape, not free-form — a required `kind` descriptor plus optional `message` / `error`, and any extra fields you need:

```ts
interface ObservabilityDetail {
  kind: string; //                  required descriptor, e.g. "fetch:error"
  message?: string; //              optional human-readable message
  error?: ObservabilityErrorInfo; // present on failures; build with toErrorInfo()
  [key: string]: unknown; //        extra structured fields — ids, timings, urls
}
```

## `toErrorInfo`

Normalizes any thrown value into the fixed error shape, for placing under `detail.error`:

```ts
interface ObservabilityErrorInfo {
  name?: string; // e.g. "TypeError"
  message: string;
  stack?: string;
  cause?: unknown; // the original thrown value
}
```
