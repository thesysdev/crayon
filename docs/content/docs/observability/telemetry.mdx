---
title: Telemetry
description: Understand the local OpenUI event model and the boundary between event production and hosted collection.
---

OpenUI runtime telemetry begins with `@openuidev/observability`, a local event bus shared by OpenUI packages in an application. The bus itself has no network transport. Hosted collection is provided separately by `@openuidev/observability-cloud`.

## Event envelope

Listeners receive an event with a severity, timestamp, and structured detail:

```ts
interface ObservabilityEvent {
  level: "info" | "warning" | "error";
  timestamp: number;
  detail: ObservabilityDetail;
}

interface ObservabilityDetail {
  id?: string;
  kind: string;
  message?: string;
  error?: {
    name?: string;
    message: string;
    stack?: string;
    cause?: unknown;
  };
  [key: string]: unknown;
}
```

The required `kind` identifies the event category. Reusing an `id` lets a producer publish successive snapshots for one logical stream or operation.

## Emit application events

```ts
import { observability, toErrorInfo } from "@openuidev/observability";

observability.error({
  kind: "checkout-card:render",
  component: "CheckoutCard",
  error: toErrorInfo(error),
});
```

Custom fields should be structured and intentionally chosen. Avoid placing credentials, secrets, or unnecessary personal data in an event payload.

## Three different telemetry systems

- **Local runtime events:** produced by `@openuidev/observability` and kept inside the application unless a listener forwards them.
- **Hosted production telemetry:** sent by `@openuidev/observability-cloud` to OpenUI Observability.
- **OpenUI Lang project telemetry:** limited installation and opt-in usage metrics documented separately in [OpenUI Lang Telemetry](/docs/openui-lang/telemetry).

Keeping these boundaries explicit lets applications use local events or custom sinks without enabling hosted collection.
